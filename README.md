# 💧 AquaTwin AI

**A physics-informed digital twin of a city water distribution network for leak detection, leak
localisation, water-loss estimation and predictive maintenance.**

AquaTwin builds the city's water network twice: a **ground-truth world** solved from hydraulic
equations, and an **observed world** seen through noisy, drifting, lossy sensors. AI is trained and
audited where the answer is known, then runs on observations only. A utility can therefore connect
real SCADA/AMI feeds later without changing the architecture.

```
CAUSE (33 scenarios) ──▶ PHYSICS (EPANET-grade GGA solver) ──▶ OBSERVATION (sensor + comms reality)
                                         │                                  │
                                 Ground-Truth World                  Telemetry contract
                                         │                                  ▼
                                   scoring only ◀──── AI: XGBoost detection · GNN localisation ·
                                                       failure/RUL · water balance · SHAP
```

Randomness is confined to sensors, communications and environmental uncertainty. Hydraulic reality
is never sampled, and an automated test proves it.

## Highlights

* **Real hydraulics:** Global Gradient Algorithm (the EPANET 2 method) with Hazen-Williams friction,
  pump curves and level controls, tanks, pressure-driven demand, **FAVAD leak emitters at the exact
  leak position**, Joukowsky water hammer, and stress-strength pipe failures. The mass-balance audit
  is below 1e-6 m³/s on every step.
* **10 immutable physical truths encoded as tests** (`tests/test_physical_truths.py`), plus a
  causality test and a perfect-twin test (at L0, observed − expected = 0 exactly).
* **Engineered city:** DMAs, a WTP reservoir → pumping station → elevated tanks, hydraulically sized
  pipes, era-dependent materials, and a *simulated* break/repair history with a renewal policy.
* **33 scenarios × 6 realism levels**: normal ops, leaks, sensor faults, comms faults,
  infrastructure, environment, and compound events. Every event carries a causal explanation.
* **Dataset:** 463k pipe records (Parquet + CSV), node/system tables, 546k raw telemetry packets
  with latency and duplicates, a 900-sample GNN leak sweep, and an asset-history panel. Truth and
  observations are stored side by side with provenance tags.
* **AI:** XGBoost detector on twin residuals (feature selection, class balancing, out-of-fold
  thresholds, alarm persistence). **Physics-informed GNN** (GCN, GraphSAGE and GATv2 compared)
  predicting pipe, position and distance from the junction, benchmarked against the classical
  sensitivity-matrix method. XGBoost failure risk + RUL. DMA water balance + MNF. SHAP and GNN
  saliency explanations.
* **Product:** Streamlit + Folium GIS dashboard with a live **Digital Twin Control Panel**, FastAPI
  (including a real-sensor `/ingest/telemetry` endpoint), Docker, a model registry with data
  lineage, and a realism-level evaluation suite.

## Results

See [`reports/training_report.md`](reports/training_report.md) and
[`reports/evaluation_levels.md`](reports/evaluation_levels.md) (regenerated by `python -m aquatwin all`).

### Held-out test (unseen episodes, all realism levels)

| Service | Result |
|---|---|
| **Leak detection**, network alarm | precision **0.92**, recall 0.58, F1 0.71, ROC-AUC 0.90. **0/5 leak episodes missed**; mean delay 2.4 steps (36 min) |
| Leak detection, pipe level (ranking) | ROC-AUC **0.968**; true pipe in top-5 for 67% and top-10 for 78% of leak steps |
| **Leak localisation** (GraphSAGE, sweep validation) | median **125 m**, top-1 0.44, top-5 0.78, ≤ 250 m 66%. Classical sensitivity method: 235 m, 0.26, 0.58, 51% |
| **Failure risk** (GroupKFold by pipe) | MAE 0.007/yr, RMSE 0.017, R² **0.76**; next-year break AUC 0.72; top-10% list captures 32% of breaks |
| **Remaining useful life** | MAE 4.2 y, RMSE 6.0 y, R² **0.94** |
| **Water-loss estimation** (DMA balance) | MAE 1.1 L/s, correlation 0.76 with true loss |

### Under increasing realism (fresh episodes + a ~180-snapshot localisation benchmark per level)

| Level | Leak episodes detected | Alarm F1 (leaks ≥ 1 L/s) | False-alarm steps | GNN loc. median / mean (m) | Classical mean (m) | Loc. ≤ 250 m | Failure R² (unseen city) |
|---|---|---|---|---|---|---|---|
| L0 Perfect | 3/3 | 0.99 | 0 | 133 / 173 | 272 | 73% | 0.78 |
| L1 Sensor noise | 4/4 | 0.83 | 1 | 149 / 275 | 508 | 66% | 0.78 |
| L2 Comms noise | 4/4 | 0.79 | 21 | 140 / 329 | 486 | 65% | 0.77 |
| L3 Degradation | 3/4 | 0.80 | 6 | 148 / 300 | 615 | 60% | 0.79 |
| L4 Compound | 2/3 | 0.80 | 1 | 174 / 343 | 637 | 65% | 0.78 |
| L5 Urban ops | 4/4 | 0.80 | 3 | 118 / 257 | 618 | 73% | 0.76 |

Reading the numbers honestly:
* The physics-informed GNN **cuts the mean localisation error by 32-58%** relative to the classical
  model-based method at every level from L1 to L5. At L0 the classical method's median is slightly
  better, because noise-free residuals are exactly what that method assumes.
* Detection is robust to noise, comms loss and compound events thanks to the twin residuals and the
  calibrated alarm: per-pipe normal baselines and a 5% false-alarm budget. **Small leaks (< 1 L/s) sit
  below the physical sensing floor** of pressure/flow monitoring at 50% logger coverage. They drive
  the remaining false-negative steps, and closing that gap is what acoustic fusion is for (see roadmap).
* Failure-model scores come from an **unseen city** with degraded inspection data, so there is no
  pipe overlap with training.

## Visual explorer

`ui/aquatwin_explorer.html` is a self-contained page: open it in any browser, with no server and no
map tiles. It replays four real twin runs on the network drawn from the model's own coordinates:
* Large leak at the evening peak
* Burst followed by valve isolation
* Leak with the nearest logger dead
* Leak hidden by a heatwave demand surge

For each run you can step through time and watch the leak-probability, pressure-residual, pressure,
health, risk and material layers. The page also shows the alarm-score and water-loss timelines, the
decision log with SHAP reasons, GNN candidates with their distance to the true leak, the asset risk
ranking, and the realism-level evaluation. Rebuild it after retraining with `python -m aquatwin ui`.

## Quick start

```bash
pip install -r requirements.txt
python -m aquatwin all            # simulate → train → evaluate  (or: --config configs/quick.yaml all)
streamlit run dashboard/app.py    # http://localhost:8501
uvicorn aquatwin.api.main:app     # http://localhost:8000/docs
pytest -q                         # 50 tests: physical truths, all scenarios, causality, ingestion
```

Docker: `docker compose build && docker compose --profile batch run --rm pipeline && docker compose up api dashboard`

Other commands: `python -m aquatwin scenarios` (catalogue with rules), `make help`-style targets in the `Makefile`.

## Going live with real sensors

1. Replace `generate_network` with an import of the utility GIS (the `WaterNetwork` graph schema),
   and calibrate the twin using the exported `network.inp` in EPANET/WNTR.
2. Point SCADA/MQTT/AMI adapters at `POST /ingest/telemetry`, which uses the same packet schema as
   the simulator.
3. Keep every AI service, the dashboard and the API. The simulator remains the augmentation engine
   and the regression-test bench (realism levels 0-5) for each model release.
